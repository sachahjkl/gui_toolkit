**A test session leaves its fonts behind no more on Windows**: a font from memory has the bytes' own key now (a hash of them and their length) in DirectWrite's shared factory, which caches files by key for the process. It had a key of its own each time it was loaded, so every font.State that ended left its faces in that cache, about two megabytes a test session, until a package of a hundred and more sessions ended the process at about the hundred and twentieth, whichever test that was. The same font loaded again meets its faces there. And `render.destroy` lets the GPU finish what it was given first (Direct3D 11: an event query; WebGPU: a poll that waits): an offscreen frame is only flushed.
