**A view detaches into a window of its own**: "Detach into a window" in a view's header and menu, and the palette's "Open <title> in a window", put the view in a window of the system, with no frame where it shows nowhere and no flash: the old place stays until the window's first picture is out. The window's header has Re-attach and Close view; Escape and Ctrl+W close the view; the system's close of the window brings the view back home, still open. The focus goes into the window and back to the main one when it closes. On Windows and X11, a floating window let go outside the main window opens in a window there, and a view's window dragged by its header onto the main window's dock targets docks again; on Wayland the buttons and the menus do it (`platform.positions_known`, asked at run time). The window's size and place are remembered, and a view open at quit opens there again. `host.view_windows(&app.main)` is the backend for a `host` program (`ui.views_set_windows`); `session.view_windows(s)` the one of the tests, with `session.view_window`, `session.window_shown` and `session.system_close`. `View_Options.moved` is called when the view changes window; the scroll and the focus follow it (`ui.state_carry`); its settings follow the main window's (`ui.style_follow`). Without a backend, or when the system refuses a window, the view floats inside its window and says so. The `docking` example shows every presentation.
