**Menus have one stem and an id, as widgets do**: a menu is named by a string `id` (the window's), opened by one `menu_open(id, at, anchor, from_keyboard, search, nested)` where `at` is a point or a rect (`Menu_At`), and built by one `menu(id, width)`, nested or not. `search` is on wherever the menu opens: a menu of a few fixed choices says `search = false`.
  - `ctx_menu(key, w)` and `menu_nested(key, w)` → `menu(id, w)`
  - `ctx_menu_open(key, pos, …)` → `menu_open(id, pos, …)`; `ctx_menu_open_rect(key, rect, anchor, kb)` → `menu_open(id, rect, anchor, kb, search = false)` to keep it as it was
  - `menu_nested_open(key, pos)` and `menu_nested_open_rect(key, rect)` → `menu_open(id, at, nested = true, search = false)`
  - `ctx_menu_close` → `menu_close`, `ctx_menu_is_open(key)` → `menu_is_open(id)` (any level), `ctx_menu_any_open` → `menu_any_open`
  - `ui.key_from_string(0, "x")` given as a menu's key → `"x"`; `menu_bar_button` and `field_menu` give and take the id
